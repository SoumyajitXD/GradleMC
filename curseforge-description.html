Troubleshooting without ritual sacrifice

Modded Minecraft problems are rarely solved by deleting half the mods, changing twelve JVM arguments and hoping the loading screen feels spiritually faster.

GradleMC gives players, modpack creators, server owners, testers and developers a structured way to inspect a modded instance before changing it. It surfaces relevant environment details, observes bounded runtime signals and turns collected evidence into readable local output.

One workflow. Four steps.

01 — Inspect the environment

Review Minecraft, loader, Java and GradleMC versions alongside loaded mods, configuration state, important paths, memory conditions and surrounding runtime context.

02 — Measure bounded runtime behaviour

Observe FPS, frame behaviour, TPS/MSPT, memory pressure, entity density, block-entity density, world-generation activity and lightweight profiling signals where supported by the installed build.

03 — Interpret the evidence

Use local rule-based Smart Diagnostics to connect available signals, identify missing evidence and present scored, prioritised guidance with supporting context.

04 — Export something useful

Generate readable reports, profiler summaries and issue bundles for bug reports, support requests, controlled comparisons and ongoing modpack maintenance.

Core capabilities

Diagnostics control centre

  • Open the in-game interface with /gradlemc gui or the configurable GradleMC keybind.
  • Access checks, runtime status, reports, overlay settings and diagnostic actions from one place.
  • Use the established GradleMC interface refined for the Forge 1.20.1 v1.0.4 release.

Environment and mod inspection

  • Minecraft, loader, Java and GradleMC build information.
  • Loaded-mod summaries, counts, searches and inspection tools.
  • Configuration, report and other relevant local paths.
  • JVM memory state and useful runtime context.

Performance evidence

  • Current FPS, optional average FPS and bounded timed FPS tests on supported clients.
  • TPS/MSPT-related observations for supported server environments.
  • Memory, entity, block-entity and world-generation pressure signals.
  • Bounded tick, CPU-lite, memory-lite and combined profiler summaries.
  • TXT and JSON output for review and comparison.

Smart Diagnostics

  • Local rule-based diagnostic scores and prioritised advice.
  • Supporting evidence, confidence context, trends and missing-data warnings.
  • Adaptive local observations without cloud inference or hidden remote processing.

Reports and issue bundles

  • Readable diagnostic reports for focused troubleshooting.
  • Recent-report discovery through commands and the GUI.
  • Profiler summaries and locally stored profile files.
  • Reviewable issue bundles for support requests and reproducible bug reports.

GradleMC profiling is intentionally bounded and transparent about its limits. It is not pretending to be async-profiler in a trench coat.

Improved in v1.0.4

  • Improved FPS measurement consistency across the overlay and timed FPS tests.
  • Added independent controls for current FPS, average FPS and GradleMC overlay branding.
  • Made the GradleMC overlay label optional and disabled by default.
  • Fixed content overlap and usability problems in the Quick Actions tab.
  • Reduced duplicated FPS and render measurement work.
  • Moved runtime sampling toward safer tick-driven measurement.
  • Improved client and integrated-server performance data coordination.
  • Strengthened diagnostic validation and internal self-test coverage.

Important: GradleMC is a diagnostics mod, not a magic performance patch. Better measurements can reveal why performance is poor; they cannot negotiate extra frames from hardware that has already filed for bankruptcy.

Client and server roles

Install on the client for

The diagnostics GUI, configurable keybind, optional overlay, current and average FPS information, timed FPS tests and client-side environment context.

Install on the server for

Server commands, permission-controlled tests, TPS/MSPT observations, memory and environment reports, loaded-mod inspection, world-generation observations, profiling, issue bundles and Smart Diagnostics summaries.

Install GradleMC on both sides when an investigation needs both client and server evidence. Client-only features cannot run from a dedicated-server console because, despite decades of technological progress, a console is still not a Minecraft window.

Installation

  1. Open the GradleMC Files page.
  2. Choose the file matching your exact Minecraft version and loader.
  3. Use the Java version required by that Minecraft release.
  4. Place the downloaded jar in the instance or server mods folder.
  5. Launch the client or server.
  6. Run /gradlemc to inspect the command tree available in that build.

Exact-match rule: Forge, Fabric, NeoForge and Quilt jars are not interchangeable. Minecraft versions are not interchangeable either. Renaming a jar changes its filename—not its loader, bytecode or relationship with reality.

Essential commands

Commands are lowercase. Permissions, environment and side availability still apply.

  • /gradlemc — show the installed build’s command help.
  • /gradlemc gui — open the in-game diagnostics interface.
  • /gradlemc status — show a compact diagnostics summary.
  • /gradlemc version — show GradleMC, Minecraft, loader and Java context.
  • /gradlemc memory — inspect JVM memory information.
  • /gradlemc check — run local environment and stability checks.
  • /gradlemc testfps start <seconds> — begin a bounded client FPS test.
  • /gradlemc testfps stop — stop the active FPS test.
  • /gradlemc perf start <seconds> — begin a bounded server performance sample.
  • /gradlemc export — export local troubleshooting evidence.
  • /gradlemc reports latest — locate the newest generated report.
  • /gradlemc smart score — inspect the current Smart Diagnostics score.
  • /gradlemc smart advice — inspect prioritised local diagnostic guidance.

Additional commands may be available for profiling, loaded mods, entities, world generation, reports, issue bundles, rules and other diagnostic systems. Use /gradlemc to inspect the command tree supplied by your exact build.

Reports and generated files

GradleMC stores its local diagnostic output beneath:

<gameDir>/gradlemc/

Depending on the installed build and action used, this can include diagnostic reports, exports, issue bundles, profiler output, local rules and supporting evidence.

Review files before sharing them. Diagnostic output can contain local paths, Java information, mod names, loader details, instance information and system context. GradleMC does not automatically upload generated files.

Local by design

  • No behavioural telemetry.
  • No analytics tracking.
  • No cloud AI or LLM integration.
  • No hidden remote diagnostic inference.
  • No automatic report upload.
  • No broad scanning of unrelated private files.
  • Generated evidence remains local until you choose to share it.

Smart Diagnostics is not generative AI. It is a local rule-based system that evaluates available GradleMC evidence, identifies missing information and produces scored, prioritised guidance.

Honest limitations

  • Not a crash-fixing bot: GradleMC can expose useful evidence; it cannot automatically repair every broken modpack.
  • Not an optimisation mod: it measures performance but does not replace Sodium, Embeddium or careful configuration.
  • Not a deep-profiler replacement: difficult CPU, allocation or tick investigations may still require Spark, VisualVM, Java Flight Recorder, async-profiler or another specialist tool.
  • Not a universal jar: every loader and Minecraft release requires its matching build.
  • Not a Bedrock tool: GradleMC targets supported Minecraft Java Edition releases.
