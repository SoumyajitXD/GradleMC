## Duplicate and hot-path findings

* Before this increment, `ClientEventHandler` invoked both overlay and FPS-test
  frame handlers on every active rendered frame. The overlay owned a rolling
  sampler and the test owned its own timestamp interval. The frame producer is
  now `MeasurementHub`; the test is a bounded subscriber.
* The overlay no longer recalculates line widths when the refreshed line list is
  unchanged. It still has separate memory, system, CPU, GPU and integrated
  server reads; these remain migration work and are deliberately documented.
* `ServerHealthTelemetry`, `PerformanceTestManager`, `WorldgenObservationManager`
  and profiler tick capture still have overlapping server-tick views. No source
  was deleted until consumer-parity migration is implemented.
* Adaptive evaluation and GUI-status packets are server-authoritative but are
  currently scheduled by the fixed 40-tick path; unchanged-state suppression is
  not yet complete.
* Known worker owners are Foundation, profiler report/sampler, and investigation.
  They are not yet one consolidated runtime-execution service.

## Executor inventory checkpoint (2026-07-24)

* `FoundationEngine`: bounded `ThreadPoolExecutor`, core 1/max 2, queue 16,
  30-second keep-alive, `GradleMC-diagnostic-N`, abort rejection.
* `InvestigationSessionService`: one worker with direct hand-off
  `SynchronousQueue`, 30-second keep-alive, `GradleMC-investigation-N`, abort
  rejection.
* `GradleMcProfilerService`: one report writer, queue 2, 30-second keep-alive,
  `GradleMC-profile-report`, abort rejection.
* `ThreadSampler`: separate `newSingleThreadScheduledExecutor`, currently an
  unbounded scheduled queue, `GradleMC CPU-lite sampler`.

This is the pre-consolidation evidence. The first three are bounded individually,
but they are not a single owned runtime service; the sampler is specifically a
remaining Phase 3E defect and must be redirected before the execution portion
can be accepted.

## Signal classification

Essential lifecycle: server stop/start, client world transition, game-thread
bridge. Cheap shared: frame timestamps while demanded and server tick duration.
Optional dynamic: FPS percentiles, memory/system metrics, entity/block-entity
inspection, profiler data and GUI-only diagnostics. Expensive foreground-only:
reports, profiler sessions, entity/block-entity scans, worldgen/performance
tests, and static analysis.

Persistent task cache/history is explicitly outside this phase.
