## Actual pre-edit inventories

* Active legacy GUI sections: Overview, Quick Actions, Tests, Profiler,
  Reports, Settings, and About. A second `GradleMCScreen`/`WorkspacePage`
  family is present in source and is not the intended active screen.
* Overlay fields: master enabled; mode; position; scale; background enabled and
  opacity; sampling window; update interval; title; FPS; average FPS; 1% low;
  0.1% low; JVM memory; system memory; CPU; GPU name; GPU usage; integrated
  server; test status; profiler status; stability.
* Measurement producers: one post-GUI frame hook; one `Runtime.getRuntime()`
  heap collector in `MeasurementHub`; one START/END server timing channel in
  `MeasurementHub`; profiler still has an independent session tick duration
  fallback; issue bundles directly call `MinecraftServer#getAverageTickTime()`.
* Executor owners: `FoundationEngine` (1–2 threads, queue 16); investigation
  service (one thread, `SynchronousQueue`); profiler writer (one thread, queue
  2); `ThreadSampler` (one scheduled executor with an unbounded queue).
* Packet families and directions, command literals, all config fields, and GUI
  pages require final source-derived inventories after the disabled deferred
  surface and the runtime migration are complete. This document deliberately
  does not pretend that an incomplete source grep is final verification.

## Scope freeze decision

### Must finish for v1.0.4

| System | Freeze decision |
| --- | --- |
| Legacy GUI and overlay controls | Keep the established legacy UI; complete lifecycle/layout safety only. |
| Frame, heap, and server timing | One shared bounded producer per ordinary channel; consumers use immutable snapshots. |
| Profiler and issue bundle | Migrate timing/evidence reads to shared snapshots; bounded lifecycle and reporting. |
| Runtime execution | Replace the separate worker owners and unbounded sampler queue with bounded, owned lanes. |
| Performance Modes and Guard | One immutable policy applied to GradleMC-owned optional work, with explainable evidence. |
| Adaptive diagnostics | Complete material-state evaluation and authoritative packet suppression. |
| Overhead, tests, reports, configuration, commands, packaging | Complete only the existing release-facing paths and validate them. |

### Explicitly deferred beyond v1.0.4

Persistent execution history/task-result cache; public extension API; runtime
plugin JAR loading; task-profile system; task-runner GUI; user-facing JFR;
multi-loader orchestration; scripting; remote services/caches; automatic
third-party optimisation/configuration changes. The currently exposed command
families for task history, workflows, scans, runs, gates, experiments,
incidents, instance locks, startup/reload/network/storage platform operations,
and investigation sessions are not v1.0.4 promises. They must be removed from
registration/help/GUI or changed to a clear deferred response before release.

## Known blockers at the freeze point

1. Project `AGENTS.md` incorrectly calls this checkout 1.1.0 and names a 1.1.0
   artifact, contrary to the actual build constants and release target.
2. No configuration migration implementation or complete round-trip suite has
   been demonstrated.
3. No release-quality GameTest, smoke, JFR, A/B, TLS, direct-JAR, or visual
   evidence exists for this exact baseline.
4. The in-app Browser requested for visual work was unavailable. A separate
   Chrome session was intentionally not substituted.
