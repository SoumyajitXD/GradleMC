# GradleMC v1.0.4 release-candidate readiness

## NOT READY

2026-07-25 final-closure attempt: **NOT READY**.  A Java 17 clean compile, unit
tests, GradleMC deterministic self-test, GameTests (13/13), and build passed after
the focused policy/guard/overhead/command-tree changes.  The build JAR from that
attempt is 1,985,513 bytes, SHA-256
`A62FD0E0CC05ADC7C586C3BD7088B1F5315F2BD2968892481204036C1E1C033C`.

It is deliberately not exported.  Release blockers remain: the issue bundle still
does not use one complete immutable client-FPS/Technical-Stability/Adaptive-Risk
operation snapshot; the adaptive proof suite and configuration migration/round-trip
suite are incomplete; no bounded dedicated-server/client command interaction smoke
or JFR/fallback review has closed their required scenarios; and the focused release
security review has not completed its required path-by-path validation.  The
unavailable in-app Browser is only a non-critical visual-verification limitation,
not the reason for this verdict.

Follow-up evidence: the release JAR now excludes `GradleMcGameTests` and
`gameteststructures` while the development GameTest run still passes 13/13.  A
bounded `runFinalizationServer` reached `Done` as GradleMC 1.0.4 and processed a
graceful console `stop` without a GradleMC classloading failure.  Its isolated
working directory contains pre-existing world metadata from a 1.1.0 run, which
Forge reported as a version difference; this is test-environment residue, not an
active version fallback, and was not deleted.

Release blockers still present:

1. Performance Mode is not yet consumed by all required measurement,
   report-detail, work-lane, and Guard paths.
2. Performance Guard is not connected to enough real optional GradleMC work and has
   neither complete unavailable-evidence handling nor the required explainable
   affected-work/recovery evidence.
3. Issue-bundle snapshots still lack a complete shared immutable FPS,
   Technical Stability, and Adaptive Risk evidence model.
4. The requested adaptive proof suite and configuration migration/round-trip
   coverage have not been implemented.
5. Deferred task/workflow/scan/platform command families remain registered;
   they have not yet been removed or clearly deferred from the release command
   tree.
6. Dedicated-server and client interactive smoke testing, JFR/internal-profile
   review, and the focused final security verification have not been completed.

No artifact was exported to `Downloads`, no Git repository was initialised or
pushed, and no publication occurred.
