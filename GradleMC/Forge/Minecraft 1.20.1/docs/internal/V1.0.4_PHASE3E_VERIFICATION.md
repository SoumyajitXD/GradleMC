The historical aggregate source hash is not used as equivalence evidence because
its input set and serialisation were not recorded.  Phase 3E now uses this exact
deterministic source-tree procedure:

1. Include every regular file recursively under `src`, `gradle`, `scripts`, and
   `docs`, plus root `build.gradle`, `settings.gradle`, `gradle.properties`,
   `gradlew`, `gradlew.bat`, `AGENTS.md`, `CHANGELOG.md`, and `LICENSE`.
2. Exclude generated/runtime directories by construction: `.gradle`, `build`,
   `run*`, `logs`, and `.prompt-artifacts` are not input roots.
3. Sort each included file by its project-relative path using `/` separators.
4. SHA-256 each file's raw bytes.  For each sorted file, create a record by
   hashing UTF-8 `relative-path + LF + lowercase-file-sha256 + LF`.
5. Join the lowercase record hashes with LF, append one final LF, and SHA-256
   those UTF-8 bytes.  This makes both the included paths and contents part of
   the aggregate without relying on timestamps or platform directory order.

## Verified frame channel

Static inspection confirms that `ClientEventHandler.onRenderGui` is the only
Forge post-GUI rendered-frame producer. `FpsTestManager` is a hub subscriber;
the overlay reads the hub snapshot; no GUI, report or diagnostic code registers
a second rendered-frame listener. The hub now removes an owner's callback on
owner release, makes handle close idempotent, isolates subscriber failures and
coalesces a repeated subscriber owner to a single callback. The pre-existing
overlay layout cache still recalculates widths only when formatted lines change.

## Shared memory channel

Added `MemorySnapshot` and `MeasurementHub.memorySnapshot`. The producer is
`Runtime.getRuntime()` in one place; its samples are immutable, heap-only and
bounded to 32 primitive trend entries. The source compatibility facade,
`RuntimeSnapshots.memory`, reads the hub. `/gradlemc memory` has an immediate
foreground refresh without a retained subscription. The overlay acquires and
releases low-frequency JVM-memory demand with its visibility. No disk writes,
`System.gc`, RAM-cleaner operation or native-memory claim was added.

## Server/adaptive implementation checkpoint (not completion)

Added a focused `ServerPerformanceChannel` with a 240-sample primitive ring and
immutable `ServerPerformanceSnapshot`. The common server hook records START to
END timing once per completed tick. Overlay integrated-server presentation,
health command, performance-test sampling, and worldgen observation now read
that channel rather than `MinecraftServer#getAverageTickTime`. The old
`ServerHealthTelemetry` has not yet been deleted because report/profiler
migration is incomplete.

Adaptive status synchronization now carries a stable material digest composed
of score, threat class, advice/factor strings and cooldowns. Repeated unchanged
sample states are suppressed; explicit requests and player login force a send.
Bounded in-memory counters record requested/skipped evaluations and sent/
suppressed/explicit/login snapshots. This is an incremental correctness change,
not the required complete dirty-state/rule-indexing implementation.
